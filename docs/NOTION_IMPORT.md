# 노션 대관 신청 가져오기

노션 **대관 신청 목록**(데이터 소스 `3669b99c-27e2-804f-ab17-000b3670fc66`)에 있는 신청을 대관 시스템으로 옮긴다.

## 무엇을 가져오나

| 항목 | 규칙 |
|---|---|
| 대상 | 공간 사용 희망일(**시작일**, 한국 시간)이 기준일(기본 **2026-10-15**) 이후인 신청 |
| 노션 상태 | 승인·접수 전·검토 중·결재 중·보류만 가져온다. **반려·취소는 가져오지 않는다** |
| 가져온 뒤 상태 | **입금 대기(미결제)**. 계좌이체 결제 대기로 만들고, 그 시간을 달력에서 잡아 둔다 |
| 금액 | 시스템의 **지금 요금표**로 계산한다(노션에는 금액이 없다). 입금 확인 전에 담당자가 금액을 확인한다 |
| 알림·자동 취소 | 신청자에게 메일을 보내지 않는다. 입금 기한 알림과 기한이 지났을 때의 자동 취소도 하지 않는다. 담당자가 **입금 확인** 또는 **반려**로 처리한다 |
| 중복 | 노션 페이지 ID를 기록해 둔다. 다시 실행해도 이미 가져온 신청은 건너뛴다 |
| 일정이 겹칠 때 | 노션 상태가 **승인**인 신청을 먼저 넣는다. 그래서 승인된 신청과 승인 전 신청이 겹치면 **승인된 신청만** 들어오고, 승인 전 신청은 "일정이 겹쳐 못 가져온 신청"에 노션 상태와 함께 나온다. 같은 상태끼리는 이른 일정부터 넣는다. 이미 가져온 신청은 바꾸지 않는다 |

노션 항목은 이렇게 옮긴다.
- 행사/공연명 → 행사명
- 신청공간 → 공간
  - 세미나실, 회의실 1·2, 교육실, 다목적홀은 같은 공간으로 연결한다.
  - **기타공간**은 시스템의 **라운지 숨:** 공간으로 연결한다(이름의 띄어쓰기·문장부호는 따지지 않는다). 시스템에 그 공간이 없으면 "시스템에 '라운지 숨:' 공간이 없음"으로 건너뛰니, **공간 설정**에서 먼저 만든다. 요금표에 그 공간 요금이 없으면 0원으로 들어오고 ⚠로 표시된다.
  - 공간을 여러 개 고른 신청은 공간마다 한 건씩 만든다.
- 신청단체 → 단체명. 등록번호가 있으면 단체 정보로 연결한다.
- 신청자·연락처·이메일·인원은 같은 이름의 항목으로 옮긴다.
  - 인원은 "20명 내외"처럼 적힌 글에서 숫자를 읽는다.
- 신청기기 → 행사 내용에 메모로 남긴다.
- 신청등록일 → 접수일

## 처음 한 번: 노션 API 토큰 만들기

노션은 이전의 "통합(integration)"을 **연결(connection)**로 바꾸고, 토큰을 **개발자 포털**에서 만들게 했다(2026-10 확인).
두 방법 중 하나를 쓴다. 어느 쪽이든 토큰은 비밀번호처럼 다룬다.

### 방법 A (권장): 개인 액세스 토큰(PAT)

토큰을 만든 사람의 권한으로 읽는다. 그래서 그 사람이 세 데이터베이스를 볼 수 있으면 **따로 연결할 필요가 없다**.

1. 노션 **개발자 포털 → Personal access tokens → New token**을 누른다.
2. 이름을 넣고 기능은 **Notion API**를 고른다. 워크스페이스를 고르라고 하면 기념관 워크스페이스를 고른다. 그다음 **Create token**을 누른다.
3. 토큰은 한 번만 보이니 바로 복사한다.
   - 만료일을 정하지 않으면 1년 뒤 만료된다. 다시 가져올 때 만료됐다면 새로 만든다.
- Business·Enterprise 요금제는 PAT 생성이 기본으로 막혀 있다. 이 경우 워크스페이스 소유자가 **설정 → 연결(Connections)**에서 허용해야 한다.
- 토큰을 만든 사람이 퇴사하거나 PAT 권한이 회수되면 그 토큰은 동작하지 않는다.

### 방법 B: 내부 연결(Internal connection)

담당자가 바뀌어도 계속 쓸 토큰이 필요할 때 쓴다. **워크스페이스 소유자**만 만들 수 있다.

1. 노션 **개발자 포털 → Build → Internal connections**에서 새 연결을 만들고 기념관 워크스페이스를 고른다.
   - 노션 앱의 **설정 → 연결(Connections)**에서도 만들 수 있다.
   - 기능(capabilities)은 **콘텐츠 읽기**만 켠다.
2. **Configuration** 탭에서 API 토큰(`ntn_…`)을 복사한다.
3. 이 연결에 데이터 접근 권한을 준다. 다음 세 데이터베이스 모두 필요하다(관계된 공간·단체 이름을 읽기 위해).
   - 대관 신청 목록, 전태일기념관 공간, 이용 단체
   - 각 데이터베이스의 **••• → 연결 추가(Add connections)**에서 방금 만든 연결을 고른다. 세 데이터베이스를 담은 상위 페이지에 한 번 추가해도 된다(하위 페이지에 함께 적용된다).

## 실행 (운영 서버)

```bash
cd /srv/taeil/deploy

# 0) 토큰을 입력한다(화면에 보이지 않고, 명령 기록에도 남지 않는다). 붙여 넣고 Enter
read -rs NOTION_TOKEN && export NOTION_TOKEN
C="sudo --preserve-env=NOTION_TOKEN docker compose -f docker-compose.prod.yml --env-file .env"

# 1) 미리보기: 저장하지 않고 결과만 본다
$C run --rm --no-deps -e NOTION_TOKEN web pnpm import:notion --exclude "[기]"

# 2) 결과가 괜찮으면 백업 후 저장
sudo ./backup.sh
$C run --rm --no-deps -e NOTION_TOKEN web pnpm import:notion --exclude "[기]" --apply

# 3) 끝나면 토큰을 지운다
unset NOTION_TOKEN
```

- 서버에 최신 버전이 배포되어 있어야 한다(`sudo ./deploy.sh`).
- `sudo`는 환경 변수를 넘기지 않으므로 `--preserve-env=NOTION_TOKEN`이 꼭 필요하다. 빠지면 "NOTION_TOKEN 환경변수가 필요합니다"가 나온다.

옵션
- `--since 2026-11-01`: 기준일을 바꾼다.
- `--status "승인"`: 승인된 신청만 가져온다(쉼표로 여러 개).
- `--exclude "[기]"`: 행사명이 `[기]`로 시작하는 신청(기념관 자체 행사)은 빼고 가져온다.
  - 이 옵션이 없으면 자체 행사도 입금 대기·요금으로 들어온다.

## 미리보기 읽는 법

| 구분 | 뜻 | 할 일 |
|---|---|---|
| 가져올 신청 | 입금 대기로 들어올 신청과 계산된 금액 | 금액·시간이 맞는지 본다. ⚠ 표시는 자동으로 고친 내용이다(아래) |
| 이미 가져온 신청 | 전에 저장한 신청 | 없음 |
| 일정이 겹쳐 못 가져온 신청 | 같은 공간·시간에 이미 다른 신청(또는 일정 차단)이 있다. `[노션: 상태]`로 원본 상태를 보여 준다 | 대개 승인된 신청에 밀린 승인 전 신청이다. 노션에서 중복 신청인지 확인하고, 정말 둘 다 필요하면 시간·공간을 고친다 |
| 확인이 필요해 건너뛴 신청 | 시각이 없거나 이상하다. 또는 시스템에 없는 공간이다 | 노션에서 고친 뒤 **같은 명령을 다시 실행**하면 그것만 이어서 가져온다 |

자동으로 고치는 경우: **종료일**의 날짜가 시작일과 다르면(신청한 날 등이 들어간 경우) 종료 시각만 살려 시작일 날짜에 붙인다. 미리보기에 ⚠로 표시된다.

건너뛰는 경우
- 시작일에 날짜만 있고 시각이 없다.
- 종료가 시작보다 이르다.
- 이용 시각이 07:00~23:00 밖이다(대부분 오전·오후를 잘못 입력한 경우).
- 신청공간이 비었거나 시스템에 없는 공간이다.

## 가져온 뒤

- **신청 관리 → 입금 대기** 탭에 들어온다. 상세 화면에 **노션에서 가져옴** 표시가 붙는다.
- 입금을 확인하면 **입금 확인**을 누른다. 신청 내용을 이미 검토했다면 "함께 승인"에 체크한다. 받지 않을 신청은 **반려**한다.
- 처리 이력에 "노션에서 가져옴(원본 상태: 승인)"이 남고, 감사 로그에 가져온 건수가 남는다.
- 잘못 가져왔다면 저장 직전 백업으로 되돌린다(`restore.sh`, `docs/DEPLOYMENT.md` 4장). 일부만 잘못됐다면 그 신청을 반려한다.
- 테스트로 만든 신청은 시스템 최고 관리자가 상세 화면의 **영구 삭제**로 지운다(운영 매뉴얼 3.4).
