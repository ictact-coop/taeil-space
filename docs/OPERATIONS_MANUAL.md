# 관리자 운영 매뉴얼

전태일기념관 대관 담당자, 회계 담당자, 시스템 관리자를 위한 안내다.
관리자 화면 주소는 `https://<대관 도메인>/admin`이다.

## 1. 계정과 로그인

| 역할 | 할 수 있는 일 |
|---|---|
| **대관 담당**(rental) | 신청 심사(검토 시작·보완요청·반려·승인·입금 확인), 휴관일·일정 차단·교육실 접수기간 수정, 환불 처리 |
| **회계 담당**(accounting) | 신청·결제 조회, 환불 처리(계좌이체 환불 완료 기록, PG 환불 재시도) |
| **시스템 관리**(system) | 위의 모든 일, 공간·요금표·감면·정책 설정 전체 |

- **첫 로그인**: 임시 비밀번호로 들어가면 2단계 인증 등록 화면이 나온다.
  - 휴대전화의 OTP 앱(Google Authenticator, Microsoft Authenticator, 네이버 앱 등)으로 QR을 찍는다.
  - 앱에 나온 6자리 코드를 입력한다.
- **로그인할 때마다**: 비밀번호를 입력한 뒤 OTP 앱의 6자리 코드를 입력한다.
- **잠금**: 비밀번호나 코드가 5번 틀리면 잠시 잠긴다. 잠금 해제 시각이 화면에 나온다.
- **휴대전화를 바꿨거나 잃어버렸을 때, 비밀번호를 잊었을 때, 담당자가 바뀔 때**: 서버 담당자에게 요청한다. 계정 관리 화면은 아직 없어 서버에서 명령으로 처리한다(아래).

```bash
# 서버의 /srv/taeil/deploy 에서 (C는 docs/DEPLOYMENT.md 2.3의 compose 명령)
$C run --rm web pnpm admin:create --login kim --name "김담당" --role rental   # 새 계정 (임시 비밀번호 출력)
$C run --rm web pnpm admin:manage list                         # 계정 목록·상태
$C run --rm web pnpm admin:manage reset-2fa --login kim        # OTP 다시 등록
$C run --rm web pnpm admin:manage reset-password --login kim   # 임시 비밀번호 재발급, 잠금 해제
$C run --rm web pnpm admin:manage deactivate --login kim       # 퇴사·담당 변경 시 로그인 차단
```

모든 계정 변경은 감사 로그에 남고, 그 계정의 로그인 세션은 즉시 끊긴다.
- **세션**: 오래 쓰지 않으면 자동으로 로그아웃된다. 공용 PC에서는 반드시 **로그아웃**한다.

## 2. 하루 업무 흐름

1. **대시보드**에서 신규 신청, 보완 대기, 환불 실패, 오늘·이번 주 이용 일정을 본다.
2. **신청 관리**의 "처리 필요" 목록에서 오래된 신청부터 연다.
3. 신청 상세에서 심사한다(아래 3장).
4. **환불 처리**에 실패·수동 처리 건이 있으면 처리한다(아래 4장).
5. **대관 캘린더**에서 이번 달 확정 예약과 일정 차단을 확인한다.

## 3. 신청 심사

신청자가 신청서를 내고 결제를 마치면 **신청접수** 상태가 된다. 결제하지 않은 신청은 결제 유효시간이 지나면 자동으로 취소되고, 잡아 두었던 시간이 풀린다.

### 3.1 상세 화면에서 볼 것

- **자동검증**: 정원, 일정 중복, 휴관일, 단체 제한(같은 단체의 월 이용 횟수 등) 검사 결과. 통과하지 못한 항목이 빨간색으로 표시된다.
- **같은 단체번호의 다른 신청**: 사업자등록번호나 고유번호가 같은 이전 신청.
  - 단체번호를 적지 않은 신청은 "중복 여부 수동 확인"으로 표시된다. 단체 이름과 연락처로 확인한다.
- **첨부파일**: 행사계획서, 감면 증빙.
  - 내려받은 기록은 감사 로그에 남는다.
  - 파일마다 악성코드 검사 결과가 표시된다. "검사 안 됨"이면 열기 전에 PC 백신으로 검사한다.
- **감면 신청**: 증빙을 확인한다. 인정되지 않으면 보완을 요청하거나 반려한다.
- **금액·결제·환불**: 결제 금액, 결제 시도 내역, 환불 내역.
- **처리 이력, 알림**: 누가 언제 무엇을 했는지, 신청자에게 어떤 메일이 나갔는지.

### 3.2 처리 버튼

| 버튼 | 언제 | 결과 |
|---|---|---|
| **검토 시작** | 심사를 시작할 때 | 상태가 "검토중"으로 바뀐다. 다른 담당자와 겹치지 않게 표시하는 용도다 |
| **보완 요청** | 서류가 모자라거나 내용을 고쳐야 할 때 | 보완 내용을 적으면 신청자에게 메일이 간다. 신청자는 "나의 대관"에서 고쳐 다시 낸다. **보완 제출 기한**(정책 설정)이 지나면 자동으로 종료되고 전액 환불된다 |
| **반려 (전액 환불)** | 대관이 불가할 때 | 사유를 적으면 반려 메일이 가고 결제가 **자동으로 전액 환불**된다. 잡혀 있던 시간은 풀린다 |
| **승인 → 예약확정** | 문제가 없을 때 | 예약이 확정되고 확정 메일이 간다. 캘린더에 표시된다 |
| **입금 확인** | 결제 방식이 계좌이체일 때 | 통장 입금을 확인한 뒤 누른다. 이때부터 심사를 할 수 있다 |
| **내부 메모** | 언제든 | 담당자끼리만 보는 메모. 신청자에게는 보이지 않는다 |

- 반려 사유와 보완 요청 내용은 **신청자에게 그대로 보인다**. 정중하고 구체적으로 쓴다.
- 처리한 모든 일은 처리 이력과 감사 로그에 남는다. 지우거나 고칠 수 없다.

### 3.3 신청자가 할 수 있는 일

- **나의 대관**: 신청할 때 적은 이메일로 확인 코드를 받아 들어온다. 신청 목록, 상세 내용, 처리 이력을 본다.
- **보완 제출**: 보완 요청을 받은 신청을 고쳐 다시 낸다.
- **철회**: 승인 전에만 할 수 있다. 정책 설정의 "승인 전 철회 환불률"만큼 자동으로 환불된다.
- **확정 후 취소**: 아직 화면이 없다(오픈 후 2주 안에 추가 예정, 계획서 5-1). 그때까지는 아래 절차로 처리한다.
  1. 전화나 메일로 취소 요청을 받는다.
  2. 정책 설정의 "확정 후 취소 시점별 환불률"로 환불액을 계산한다.
  3. **PortOne 관리자 콘솔**에서 그 금액만큼 부분 취소한다.
  4. 신청 상세의 **내부 메모**에 처리 내용을 남긴다.

## 4. 환불

- **자동 환불**: 반려, 보완기한 만료, 승인 전 철회, 결제 기한이 지난 뒤 들어온 결제, 금액이 맞지 않는 결제는 시스템이 PG로 자동 환불한다.
- **환불 실패**: PG 환불이 5번 실패하면 **환불 처리** 목록에 "실패"로 올라온다. 신청 상세의 환불 내역에서 **다시 시도**를 누른다.
  - 계속 실패하면 PortOne 콘솔에서 결제 상태를 확인한다. 이미 취소되어 있으면 수동 완료로 기록한다.
- **계좌이체 환불**: 결제 방식이 계좌이체면 환불도 담당자가 직접 한다.
  1. 신청자의 환불 계좌로 이체한다.
  2. 환불 내역의 **환불 처리 내용**에 "○○은행 이체, 10/30"처럼 적고 완료로 기록한다.

## 5. 정책 설정

**정책 설정** 메뉴에서 운영 규칙 대부분을 코드 수정 없이 바꿀 수 있다.

| 메뉴 | 내용 | 수정 권한 |
|---|---|---|
| 개요·오픈 준비 | 오픈 전에 반드시 확정할 항목 점검, 예약 적용 대기 중인 변경 | 시스템 |
| 운영 기본 | 유료 대관 전환일, 대관 시간, 야간 대관, 동절기, 예상 심사기간 안내 | 시스템 |
| 공간 | 공간 이름, 정원, 사진, 공개 여부 | 시스템 |
| 휴관일 | 정기 휴관(매주 월요일 등), 공휴일, 임시 휴관 | 시스템·대관 |
| 일정 차단 | 기념관 자체 행사, 공사 등으로 특정 시간을 막기 | 시스템·대관 |
| 교육실 접수기간 | 접수를 여는 기간 | 시스템·대관 |
| 신청 규칙 | 신청 가능 기간, 최소·최대 이용 시간, 단체 제한 | 시스템 |
| 요금표 | 공간별 기본요금, 추가요금, 야간요금, 부대시설 | 시스템 |
| 감면 | 감면 종류, 감면율, 필요한 증빙 | 시스템 |
| 결제·환불 | 결제 방식(온라인·계좌이체), 결제 유효시간, 입금 계좌, 철회·취소 환불률 | 시스템 |
| 알림 | 입금 기한 임박 알림, 이용 전 안내 시점 | 시스템 |
| 개인정보 | 보존 기간 등 | 시스템 |
| 안내·규정 문구 | 이용자 화면의 안내문, 동의 문구 | 시스템 |
| 연동 상태 | 결제, 메일, 문자, 파일 저장소 설정 여부(읽기 전용) | — |

- **적용 시각**
  - 바꾼 값은 "지금 바로" 적용하거나 날짜를 정해 예약할 수 있다. 예: 요금 인상을 1월 1일부터 적용.
  - 예약한 변경은 적용 전까지 취소할 수 있다.
- **이미 들어온 신청은 그대로**
  - 신청 건마다 신청 당시의 요금과 정책이 저장된다.
  - 요금이나 환불률을 바꿔도 기존 신청에는 영향이 없다.
- **이력**
  - 모든 변경은 **변경 이력**에 남는다(누가, 언제, 이전 값, 새 값, 사유).
  - 되돌리려면 이전 값으로 다시 저장한다.

## 6. 감사 로그

**감사 로그**에서 다음 기록을 기간, 담당자, 대상별로 검색할 수 있다.

- 관리자 로그인
- 설정 변경
- 신청 상세 조회
- 첨부 내려받기
- 심사 처리
- 환불

개인정보 열람 기록을 확인할 때 쓴다. 기록은 지우거나 고칠 수 없다.

## 7. 문제가 생겼을 때

| 증상 | 확인할 것 | 연락 |
|---|---|---|
| 사이트가 열리지 않는다 | `https://<도메인>/api/health`가 열리는지 | 시스템 관리자(서버) |
| 신청자가 결제했는데 신청이 "결제 대기"로 남아 있다 | 5분 안에 자동 대사로 반영된다. 10분이 지나도 그대로면 PortOne 콘솔에서 결제 상태를 확인한다 | 시스템 관리자 |
| 메일이 오지 않는다고 한다 | 신청 상세의 **알림**에서 발송 상태(성공·실패)를 확인한다. 스팸함도 안내한다 | 시스템 관리자(메일 설정) |
| 환불이 "실패"로 남아 있다 | 4장의 환불 실패 절차대로 처리한다 | 회계 담당 → PortOne 고객센터 |
| 같은 시간에 두 건이 잡힌 것 같다 | 시스템이 DB 제약으로 막으므로 실제 이중 예약은 생기지 않는다. 캘린더에서 일정 차단과 헷갈린 것인지 확인한다 | 시스템 관리자 |
| 관리자가 OTP 기기를 잃어버렸다 | 서버에서 `admin:manage reset-2fa`를 실행한다(1장) | 서버 담당자 |
